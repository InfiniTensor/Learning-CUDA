# 4096 粒子混合精度实验

本实验只回答一个限定问题：在固定的 4096 粒子星团上，FP16 成对力计算能否在误差可控的前提下加快计算。它不是对其他粒子数、初态或物理参数的精度保证。

## 方法

- 设备：NVIDIA RTX 5090；CUDA 12.8。输入为 `data/cluster_4096.txt`（seed 42），配置为 `configs/cpu_4096.cfg`，Leapfrog KDK，1000 步。
- `cuda-mixed` 每次力计算前将 FP32 位置和质量打包为 `__half2`；一个线程仍负责一个目标粒子，一次处理两个源粒子。位移、距离平方、距离倒数及力贡献用 FP16x2 计算，两条通道转换为 FP32 后分别累加。位置、速度、积分和累加器保留 FP32。
- 自相互作用通道在求倒数平方根前被置为有限的单位距离、零质量，避免出现 `0 × ∞`。尾部不足一对时用零质量填充。
- 入口会检查初态坐标、质量、`G`、软化长度平方及 `G×质量` 的 FP16 可表示性；这只能阻止明显的溢出/下溢，不能保证积分过程中或中间力计算的误差边界。
- 正确性比较开启轨迹和末态诊断，以已有 CPU FP64 结果为参考。计时比较关闭轨迹与诊断，交错运行 `cuda-naive` block 128 和 `cuda-mixed` block 64 各 8 次，剔除第一组预热后取 7 次中位数；计时包含每步的 FP16 打包。输出文件写入不计入模拟时间。

## 精度

本次探索采用的接受条件：最终位置和速度的整体相对 L2 误差各不超过 0.1%；末态相对能量漂移不超过 `1e-4`，绝对动量误差不超过 `1e-6`，所有输出有限。逐粒子极值也报告，但没有把接近零的粒子分量做不稳定的相对误差判定。这些是本实验的工程判断，并非项目给定的统一精度标准。

| 指标 | `cuda-mixed` 相对 CPU FP64 |
|---|---:|
| 最终位置整体相对 L2 | `1.213622e-4`（0.012136%） |
| 最终速度整体相对 L2 | `1.412526e-4`（0.014125%） |
| 最终位置绝对误差 P95 / P99 / 最大 | `9.775857e-5` / `1.868407e-4` / `7.127996e-4` |
| 最终速度绝对误差 P95 / P99 / 最大 | `2.968754e-4` / `5.480432e-4` / `2.712266e-3` |
| 轨迹最大帧相对 L2 | `1.213630e-4` |
| 相对能量漂移 / 绝对动量误差 | `5.990496e-6` / `9.054864e-9` |

所有最终状态与轨迹元素有限，满足上述接受条件。与之相比，`cuda-naive` FP32 的最终位置/速度整体相对 L2 分别约为 `1.9893e-6` / `2.2630e-6`；混合精度确实牺牲了一部分精度，不应把它描述为与 FP32 等精度。这里的绝对误差分位数基于每粒子的三维向量范数。

## 速度与瓶颈

| 后端 | block size | 力计算中位数 | 模拟中位数 |
|---|---:|---:|---:|
| `cuda-naive` | 128 | 211.496 ms | 221.569 ms |
| `cuda-mixed` | 64 | 160.777 ms | 170.738 ms |

力计算加速比 `1.315×`，耗时下降 `24.0%`；整体模拟加速比 `1.298×`，耗时下降 `22.9%`。这些是同一台机器上的短时实测，不代表其他 GPU 的保证。对 `cuda-mixed` 的 block size 扫描中，64、128、256、512 的力计算中位数约为 160.811、165.119、172.907、213.621 ms，因此本场景使用 64。

Nsight Systems 对一次 1000 步运行统计：混合精度力 kernel 共 1001 次、GPU 总计 154.689 ms，占 GPU kernel 时间 98.4%；打包 kernel 共 1001 次、总计 0.831 ms，占 0.5%。因此打包不是当前主要开销。`cuobjdump` 确认生成了 `HADD2`、`HFMA2`、`HMUL2`，但 CUDA 12.8 的 `h2rsqrt` 仍由两条 FP32 倒数平方根操作实现，不能按“两个 FP16 通道”推断必有 2 倍速度。此前 Nsight Compute 因服务器未开放 GPU 计数器而不能读取硬件利用率，以上瓶颈判断基于 Nsight Systems 时间线与生成指令。

## 复现

```bash
source /data/nbody-dev/activate-nbody.sh
cmake --build build
ctest --test-dir build --output-on-failure

./build/nbody --backend cuda-mixed --block-size 64 \
  --input data/cluster_4096.txt --config configs/cpu_4096.cfg \
  --output results/cluster_4096_cuda_mixed_repeat
python scripts/compare_runs.py results/cluster_4096_cpu_1000 \
  results/cluster_4096_cuda_mixed_repeat
```

输出目录不能覆盖已有结果。若要复现速度测量，两个后端使用同一输入与配置，并都加上 `--record off --diagnostics off`；多次交错运行再比较中位数，避免把单次抖动当成优化效果。

当前方案的 FP16 范围有限：不同质量、较大坐标范围、不同软化长度或更长积分时间可能产生更大的量化误差，甚至发生溢出/下溢。必须在新场景重新与 CPU FP64 比较后才能采用。
