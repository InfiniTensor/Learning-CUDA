# N 体引力模拟与可视化项目总结报告

## 摘要

本项目实现了一个可复现的三维 N 体引力模拟器：读取粒子与物理配置，在 GPU 上计算引力并进行数值积分，输出二进制轨迹、末态、守恒量与性能日志，再由 Python 渲染动画。核心交付是 CPU FP64 参考实现、CUDA FP32 直接法和共享内存分块法；在此之上还完成了 CUDA 混合精度、Barnes–Hut 近似算法以及沐曦 MetaX C500 的 MACA 原生直接法适配。

项目的一个重要结论是：不能只从渐近复杂度判断实际最优方案。在 RTX 5090 的 4096 粒子场景中，直接法已经很快，共享内存分块仅有约 0.6% 的收益；混合精度可带来约 1.30 倍加速，且误差满足本项目设定的工程门槛。65536 粒子、1000 步时，固定深度 Barnes–Hut 相对直接法达到 1.768 倍加速且位置/速度相对 L2 误差低于 1%；但将同一星团延长到 2000 步后，粒子局部聚集使该固定树显著退化，GPU 直接法反而成为更快、更可靠的最终方案。因此，最终的 65536×2000 视频与国产卡适配均使用 FP32 全粒子直接求和。

除 NVIDIA CUDA 外，项目新增 MACA 构建模式和 `maca-naive`/`maca-tiled` 后端，并在 MetaX C500 上完成编译、单元测试、双体轨道、4096×1000 和 65536×2000 的端到端验证。完整代码、配置、测试和复现命令均随项目保存；本报告所列性能数字都明确标注硬件、输入和计时边界，避免将不同平台、不同轨迹记录策略的数据混为一谈。

## 1. 需求与完成范围

项目输入每行包含 `x y z vx vy vz mass`，配置文件包含 `dt`、步数、记录间隔、万有引力常数 `G`、软化长度和积分器。程序输出：

- `trajectory.bin`：小端 `int32(P,R)` 文件头，以及按粒子优先布局存储的 `float32[P,R,3]` 坐标；
- `metadata.json`、`performance.json`、`final_state.csv`；开启诊断时还输出初末能量、动量、角动量和质心；
- Python/NumPy/Matplotlib 动画。

实现的计算后端如下。

| 后端 | 精度与方法 | 适用定位 |
|---|---|---|
| `cpu` | FP64，直接全对求和 | 小规模高精度参考、诊断基准 |
| `cuda-naive` | FP32，GPU 直接法 | CUDA 正确性和性能基线 |
| `cuda-tiled` | FP32，shared-memory 分块直接法 | CUDA 内存复用实验 |
| `cuda-mixed` | FP16x2 力计算，FP32 累加与积分 | 4096 粒子上的混合精度实验 |
| `cuda-bh` | FP32、六层固定深度 Barnes–Hut 八叉树 | 65536 粒子、1000 步近似算法实验 |
| `maca-naive` | FP32、MACA 直接法 | MetaX C500 的最终大规模路径 |
| `maca-tiled` | FP32、MACA shared-memory 分块法 | C500 上的分块对照实验 |

CUDA 和 MACA 不在同一构建中混编。CMake 通过 `NBODY_GPU_BACKEND=CUDA|MACA|NONE` 选择编译路径；未启用的后端在创建输出目录之前即被拒绝，避免失败命令留下空输出目录。

## 2. 物理模型与数值积分

### 2.1 软化引力模型

对目标粒子 $i$，项目计算加速度：

$$
\mathbf a_i = G\sum_{j\ne i}m_j
\frac{\mathbf r_j-\mathbf r_i}
{(\|\mathbf r_j-\mathbf r_i\|^2+\varepsilon^2)^{3/2}}。
$$

其中 $\varepsilon$ 是 Plummer 型软化长度。实现中跳过 $j=i$，同时在分母加入 $\varepsilon^2$。这既避免自力，也避免近距离相遇时 $r=0$ 的数值奇异性。CPU 参考在 FP64 中执行同一公式；GPU 直接法在 FP32 中保存位置、速度、质量和加速度，保证比较时的物理模型一致。

总能量诊断采用相同软化模型：

$$
E=\sum_i\frac12m_i\|\mathbf v_i\|^2-
G\sum_{i<j}\frac{m_im_j}{\sqrt{\|\mathbf r_j-\mathbf r_i\|^2+\varepsilon^2}}。
$$

诊断中的势能仍是 CPU FP64 全对计算，因此大规模性能测量显式使用 `--diagnostics off`，不把诊断成本误算为 GPU 求解器耗时。

### 2.2 Euler 与 Leapfrog KDK

程序保留显式 Euler，主要用于教学和对照：

$$
\mathbf r_{n+1}=\mathbf r_n+\mathbf v_n\Delta t,\qquad
\mathbf v_{n+1}=\mathbf v_n+\mathbf a_n\Delta t。
$$

正式场景默认采用 Leapfrog 的 kick-drift-kick（KDK）形式：

$$
\begin{aligned}
\mathbf v_{n+1/2}&=\mathbf v_n+\frac{\Delta t}{2}\mathbf a(\mathbf r_n),\\
\mathbf r_{n+1}&=\mathbf r_n+\Delta t\,\mathbf v_{n+1/2},\\
\mathbf v_{n+1}&=\mathbf v_{n+1/2}+\frac{\Delta t}{2}\mathbf a(\mathbf r_{n+1}).
\end{aligned}
$$

KDK 是二阶、时间可逆的辛格式，更适合长期保留引力系统的轨道性质。它在 $S$ 步中进行 $S+1$ 次力计算：一次初始加速度计算，以及每一步漂移后的新加速度计算。例如 4096×1000 的性能日志中记录 1001 次力评估。CPU、CUDA 与 MACA 均沿用这一时序，避免“同一积分器名称但更新次序不同”的伪对照。

## 3. 软件结构与实现思路

### 3.1 参考链路

程序先严格解析输入和配置，在 CPU 端完成结构检查；然后由选定后端执行模拟。GPU 后端只在开始时把状态上传到设备，循环中让位置、速度和加速度常驻显存。轨迹记录时才将该记录帧的位置回传；末态只在模拟结束时回传。这样将 PCIe 传输限制在必要的快照与最终结果，而不是每步搬运整个系统。

CPU 参考实现为单线程 FP64 的 $O(N^2)$ 直接求和。它既用于小规模逐粒子对照，也计算守恒量；GPU 的最初目标不是取代它作为最高精度实现，而是在同一物理模型下实现可验证的并行计算。

### 3.2 CUDA 直接法与分块法

`cuda-naive` 中每个线程负责一个目标粒子 $i$，顺序读取全部源粒子 $j$ 并在寄存器中累加三个加速度分量。该方法时间复杂度为 $O(N^2)$，实现简单、访存顺序连续，是所有 CUDA 优化实验的基线。

`cuda-tiled` 将源粒子按 block size 分块。一个 block 先把当前 tile 的位置和质量读入动态 shared memory，然后 block 内每个有效目标线程复用该 tile。尾块中无效目标线程仍参与两次 `__syncthreads()`，只是不累加/写回，从而避免在块同步前提前返回造成死锁。对 RTX 5090，此优化的收益很小，这一事实在后文性能分析中说明。

### 3.3 混合精度实验

`cuda-mixed` 针对 4096 粒子实现。每次力计算先把 FP32 的位置和质量打包成 `__half2`；一个线程一次处理两个源粒子，FP16x2 用于位移、距离平方、倒数距离和力贡献的成对计算，结果转换为 FP32 后分别累加。位置、速度、积分与加速度累加始终保持 FP32。

实现中对包含自身的半精度通道设置有限距离和零质量，避免 `0×∞`；奇数尾部使用零质量补齐。还检查初值、软化长度和 `G×m` 的 FP16 可表示性。该方法是有意的精度—速度折中，不能表述为“与 FP32 等精度”。

### 3.4 Barnes–Hut 实验

`cuda-bh` 在每次力评估时于 GPU 上：计算包围立方体、清空树、把粒子插入叶节点、归约每个节点的质量与质心，再遍历树求力。树为六层固定深度八叉树，叶网格为 $64^3$。若一个远场节点满足

$$s/d<\theta,$$

其中 $s$ 为节点边长、$d$ 为目标到节点质心距离，则用该节点的单极子近似；包含目标的节点必定展开，叶内粒子仍直接求和并排除自身。采用 $	heta=0.5$，以速度换取可测的近似误差。

这种实现的优势是全流程在 GPU 上，未把 CPU 建树藏在计时外；局限是树深与叶容量固定，粒子坍缩时会造成拥挤叶节点，叶内直接求和重新变重。

### 3.5 MetaX C500 / MACA 适配

为适配沐曦 MetaX C500，新增 MACA 原生 `maca-naive` 与 `maca-tiled`。二者使用 `mxcc`、`mc_runtime.h`、`mcMalloc`/`mcMemcpy`/事件计时和 MACA kernel launch，算法与 CUDA 直接法的状态布局、Euler/KDK 时序、轨迹格式一致。公共的解析、CPU 参考、I/O 和可视化代码完全复用。

首轮移植只选择直接法，未移植 CUDA 的 FP16x2 和 Barnes–Hut：前者依赖 NVIDIA 特有半精度指令路径，后者包含复杂的树节点原子操作。这个范围控制让移植先获得可验证、可交付的 C500 大规模模拟能力，而不是在未经测试的复杂优化上扩大风险。

## 4. 优化历程、观察与取舍

### 4.1 block size 扫描：共享内存不是必然的大幅加速

在 RTX 5090、4096 粒子、1000 步、KDK、每 10 步记录的测试中，比较了 64/128/256/512 的 block size。`cuda-tiled` 的最优点为 128，模拟中位数 221.005 ms；`cuda-naive` B=128 为 222.421 ms，分块只快约 0.64%。16384 粒子、100 步的结果也相同：B=128 最优，分块仅快约 0.77%。

原因不是 shared memory 无效，而是该 GPU 上朴素内核对连续源数组的读取已受益于缓存和同一 warp 的访问合并/广播；tiled 每个 tile 还新增两次块同步。更大的 block 会提高同步、寄存器和调度压力，因此 B=256、512 均变慢。这个实验纠正了“线程块或共享内存越大越快”的直觉：最优参数必须以端到端测量确定。

### 4.2 混合精度：取得有限但可靠的收益

4096 粒子、1000 步的交错重复计时中，`cuda-mixed` B=64 的力计算/模拟中位数分别为 160.777/170.738 ms，较 `cuda-naive` B=128 的 211.496/221.569 ms 提升 1.315×/1.298×。最终位置和速度相对 CPU FP64 的整体相对 L2 误差分别为 $1.213622\times10^{-4}$ 与 $1.412526\times10^{-4}$，均低于本实验预设的 0.1% 门槛；相对能量漂移为 $5.990496\times10^{-6}$，所有输出有限。

这说明半精度在该受控星团中可用，但其收益远小于理想的 2 倍。剖析显示半精度打包 kernel 只占 GPU kernel 时间约 0.5%，主力 kernel 占约 98.4%；并且半精度倒数平方根仍会使用 FP32 指令路径，不能简单按“双通道”推断 2 倍吞吐。

### 4.3 Barnes–Hut：规模与轨迹阶段共同决定收益

65536 粒子、1000 步、关闭轨迹与诊断、同一固定种子星团上，CUDA 直接法模拟中位数为 3662.050 ms，六层 `cuda-bh` 为 2070.870 ms，得到 1.768× 加速，耗时下降 43.5%。相对于同样 FP32 的直接法，BH 最终位置/速度整体相对 L2 为 0.591%/0.746%，满足本项目设定的整体相对 L2 小于 1% 的工程门槛。

不过，4096 粒子下 BH 模拟时间约 640.079 ms，远慢于直接法约 220.954 ms；小规模没有必要切换。更关键的是，后续将同一 65536 星团扩展到 2000 步，后半程出现更强局部聚集，固定树的叶内直接求和退化。带完整轨迹的测量中，FP32 直接法模拟约 7.68 s，而原固定树约 48.25 s。此时直接法才是最终结果的正确选择。

还做了隔离的“超过 32 粒子叶节点再细分一层”原型。它在 2000 步、$\theta=0.5$ 时把树算法降到约 15.14 s，但末态位置/速度相对直接法误差约 1.23%/4.18%，不满足目标；收紧到 $\theta=0.30$ 可将误差降到约 0.25%/0.87%，但时间升至约 53.47 s。该原型没有合入主后端。结论是单层致密细分能缓解拥挤叶，却无法在这一轨迹上同时胜过直接法并保持目标误差；若继续研究，应使用递归、稀疏、自适应的树，而非继续堆叠稠密子节点。

### 4.4 I/O 也是性能的一部分

4096 粒子、1000 步的轨迹记录实验表明：关闭记录时模拟中位数为 218.246 ms；每步记录升至 246.267 ms（+12.8%），轨迹达约 49.2 MB；每 10 步记录为 221.141 ms（仅 +1.3%），轨迹约 4.96 MB。于是正式动画默认每 10 步记录一次，性能基准使用 `--record off --diagnostics off`。

这说明“kernel 快”不等于“任务快”。报告中的模拟时间包含模拟循环内必要的记录回传，但不包含输入解析、GPU 冷启动和最终文件写入；端到端冷启动时间应单列，而不应与稳态 kernel 时间混报。

## 5. 正确性验证

### 5.1 自动化测试与工具检查

CUDA 构建包含 CPU 核心、I/O、轨迹往返、步长收敛、CUDA 直接法、混合精度和 65536 粒子 BH 对照等测试。129 粒子的专门测试覆盖 64、128、256、512 线程块以及非整块尾部，并逐粒子比较 CPU FP64 与 GPU 的末态位置、速度和完整记录轨迹；CUDA 后端要求各分量最大绝对误差小于 $2\times10^{-5}$。实测最大绝对误差中，tiled 最终位置为 $7.904\times10^{-8}$、最终速度为 $8.462\times10^{-8}$、轨迹为 $8.941\times10^{-8}$。

CUDA 使用 Compute Sanitizer：

```bash
compute-sanitizer --tool memcheck ./build/nbody_cuda_tests
compute-sanitizer --tool synccheck ./build/nbody_cuda_tests
```

两项均报告 0 个错误，说明测试覆盖的 CUDA 内存访问和 block 同步路径未发现问题。

MACA 构建在 C500 上运行 5 项 CTest，全部通过。其中 `maca_backends_vs_cpu` 覆盖 129 粒子、Euler/Leapfrog、naive/tiled、64/128/256 block size、非整块尾部、轨迹开关和有限值检查。

### 5.2 二体验证

双体输入使用两个等质量粒子、初始间距 1、Leapfrog 运行 10000 步。CPU FP64 的最大相对间距误差为 $9.537\times10^{-7}$、最大质心距离为 0、相对能量误差为 $1.693\times10^{-13}$。C500 MACA tiled 的对应结果为最大相对间距误差 $1.2517\times10^{-5}$、最大质心距离 0、相对能量误差 $2.3838\times10^{-6}$，所有轨迹坐标有限。该测试同时验证了 KDK 更新、引力符号和动量对称性。

### 5.3 多体逐粒子对照

RTX 5090 上，4096 粒子、1000 步的 `cuda-naive` 相对 CPU FP64 的最终位置/速度整体相对 L2 约为 $1.9893\times10^{-6}$/$2.2630\times10^{-6}$。C500 上相同的固定种子星团、配置和 1000 步中，`maca-naive` 相对 CPU FP64 的最终位置/速度整体相对 L2 为 $1.9909\times10^{-6}$/$2.2668\times10^{-6}$；轨迹最大帧相对 L2 为 $1.9910\times10^{-6}$。`maca-tiled` 在该测试中的数值结果与 `maca-naive` 一致。

65536 粒子时，CPU FP64 全对 2000 步的成本过高，因而 CUDA BH 的精度基准明确采用同样 FP32 状态的 GPU 直接法，而不是误称为 CPU 对照。C500 的 65536×2000 MACA 直接法输出 201 帧、轨迹文件约 151 MiB，所有数值有限；该场景主要验证端到端稳定运行与轨迹可读性。

## 7. Nsight Systems / Nsight Compute 使用与分析

### 7.1 Nsight Systems 实测

为避免 I/O 干扰，使用 4096 粒子、20 步短配置、关闭轨迹和诊断进行 CUDA 时间线采样：

```bash
nsys profile --trace=cuda,osrt --sample=none \
  -o results/profiles/m5_timeline \
  ./build/nbody --backend cuda-tiled --block-size 128 \
  --record off --diagnostics off \
  --input data/cluster_4096.txt --config configs/profile.cfg \
  --output results/profiles/m5_profile_run

nsys stats results/profiles/m5_timeline.nsys-rep
```

结果共 61 次 kernel launch：21 次 `force_tiled_kernel` 总计 4.321 ms、平均约 205.8 us，占 GPU kernel 时间 99.2%；20 次 `kick_drift_kernel` 与 20 次 `final_kick_kernel` 各占约 0.8%。因此力计算而非积分更新是明确热点，现阶段把两个更新 kernel 强行融合不会显著降低总模拟时间。时间线还显示三次 `cudaMalloc` API 共约 132.4 ms，主要对应冷启动上下文初始化；所以正式性能表使用进程内模拟时间或多次重复运行，而非把首次进程总时间当作稳态性能。

混合精度的单独 Nsight Systems 统计也支持这一结论：1001 次混合力 kernel 合计 154.689 ms，占 GPU kernel 时间 98.4%，而位置打包 kernel 合计 0.831 ms，仅占 0.5%。优化目标应继续放在主力计算 kernel，而不是过早融合微小的打包步骤。

六层 BH 的 Nsight Systems 统计显示遍历 kernel 占 GPU kernel 时间约 98.5%，说明在该实现中遍历而非建树是主要成本；这与粒子聚集导致叶内直接求和重的观察一致。

### 7.2 Nsight Compute 的限制与复现命令

尝试收集 Nsight Compute 的硬件计数器时，服务器返回 `ERR_NVGPUCTRPERM`，即 GPU 性能计数器权限未开放。这是运行环境权限限制，不是 kernel 错误；因此本报告不虚构 occupancy、带宽利用率或 SM 吞吐率数值。若管理员开放权限，可使用：

```bash
ncu --set full --target-processes all \
  -o results/profiles/ncu_tiled \
  ./build/nbody --backend cuda-tiled --block-size 128 \
  --record off --diagnostics off \
  --input data/cluster_4096.txt --config configs/profile.cfg \
  --output results/profiles/ncu_profile_run
```

应重点比较 `force_naive_kernel`、`force_tiled_kernel` 和 `force_mixed_half2_kernel` 的执行时间、occupancy、global load efficiency、shared-memory 吞吐、寄存器压力及 warp stall 原因，并保持同一输入、步数、block size 和记录策略。没有计数器时，本项目仍可根据 Nsight Systems 的 kernel 占比、block-size 扫描、生成的半精度指令和重复计时做受限但可验证的判断。

## 8. 可视化与交付结果

Python 脚本读取轨迹文件头和元数据，验证字节数与形状一致后，以 memmap 访问 `[P,R,3]` 数据，渲染 XY 动画。常规显示可抽样粒子，65536 粒子的最终 C500 结果也已全粒子渲染：201 帧、30 FPS，视频约 3.8 MiB，渲染约 117 秒。渲染时间与 GPU 模拟时间分开统计，避免将离线 FFmpeg 编码混入求解器性能。

此外实现了小天体带控制组与扰动组，用于确认模拟输出不仅是数值文件，也能体现物理差异。5000 步后，按中心天体对齐，扰动组相对控制组的小天体末态位移差中位数为 0.422、最大值为 11.431；两组轨迹均有限，能量相对误差分别为 $1.87\times10^{-7}$ 与 $1.49\times10^{-6}$。

## 9. 开发中发现的问题与处理

1. **共享内存收益远小于预期。** 初期预期 tiled 会大幅减少全局访存，实际在 RTX 5090 与 C500 上都只带来极小收益甚至变慢。通过 block 扫描和 Nsight Systems 确认原因是直接法已有较好的连续访问，而同步开销不可忽略，故不将 tiled 夸大为关键优化。
2. **block size 增大并非并行度必然增加。** 每个线程已经负责一个目标粒子；更大的 block 改变的是资源占用和可并发 block 数。B=256/512 的实测结果更慢，最终统一选择 CUDA B=128；混合精度因寄存器/计算特征不同选择 B=64。
3. **FP16 的风险不止最终存储。** 自相互作用的 `0×∞`、半精度范围和尾部配对都需要显式处理。项目保留 FP32 状态和累加，并把混合精度严格限制为已验证的 4096 粒子场景。
4. **树算法不保证在更大 N 或更长时间一定更快。** 65536×1000 时 BH 有效，但 2000 步时叶节点拥挤导致退化。后续的自适应一层原型也表明，速度与误差必须同时测量，不能只报告某个较快配置。
5. **性能计时必须切开冷启动、模拟、I/O 和诊断。** CUDA 上下文初始化、轨迹传输、最终写盘和 CPU 全对势能诊断的量级不同；项目将这些成本分列并提供开关。
6. **国产卡适配不能只改编译命令。** MACA 移植要求把 CMake 从“强制 CUDA”拆为平台可选构建，新增独立运行时封装和测试，同时保持输出格式不变；这样才能复用原有 Python 工具和 CPU 参考验证。

## 10. 局限与可继续提升的方向

1. **递归稀疏自适应 Barnes–Hut。** 若继续研究近似算法，应以 Morton 编码/空间排序、紧凑节点池和递归细分替代当前固定深度树，并按叶容量与轨迹聚集情况动态控制深度；需重新测量误差—速度曲线。
2. **GPU 端诊断归约。** 当前大规模势能诊断仍是 CPU $O(N^2)$，可通过 GPU 归约或抽样诊断减少其与主模拟的耦合，但应独立验证能量计算误差。
3. **跨平台性能工程。** MACA 后端仅完成直接法基线。可用 C500 的性能分析工具、不同 block size、向量化和适合该编译器的共享内存策略继续调优；CUDA 专有 `half2` 与树原子逻辑不应机械照搬。
4. **多 GPU 与域分解。** 对更大的 N，单卡直接法的 $O(N^2)$ 最终会成为限制。多 GPU 需要粒子分区、跨卡通信和同步设计，并重新评估通信量是否抵消计算收益。
5. **更完整的数值验证。** 可增加不同随机种子、不同软化长度、不同时间步和更长物理时间下的误差统计；对混合精度与 BH 应报告分位数和能量/动量漂移，而不只给一个末态标量。
6. **受控 NCU 复测。** 在开放性能计数器权限后，补充硬件级指标并结合源代码行级 profile，验证当前关于缓存、同步和寄存器压力的推断。

## 12. 结论

项目完成了从 CPU 参考、CUDA 直接法/优化实验、65536 粒子近似算法探索到 MetaX C500 适配的完整链路。最终选择不是追求“算法看起来更复杂”，而是以同一输入、同一积分器、明确的计时边界和逐粒子误差对照来决定：4096 粒子使用混合精度直接法，65536 粒子、2000 步使用经过验证的 FP32 直接法。项目同时保留 BH、混合精度、性能剖析和自适应树可行性实验，为后续在不同规模与硬件条件下继续优化提供了可复现基线。
