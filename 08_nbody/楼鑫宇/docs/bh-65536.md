# 65536 粒子 Barnes–Hut 实验记录

本实验以 RTX 5090、CUDA 12.8 上的固定种子星团评估 `cuda-bh`，并判断 4096 粒子是否值得切换。结果不是对所有输入的速度或误差保证。

## 实现与计时边界

- 每次力评估都在 GPU 上重新求包围立方体、清空树、分配粒子到叶节点、归约质量/质心，再遍历求力。Leapfrog 1000 步共执行 1001 次；`force_total_ms` 包含全部建树和遍历工作，没有隐藏 CPU 逐步建树。
- 使用六层固定深度三维八叉树（`64³` 个叶节点）；原始粒子顺序始终不变，轨迹与最终状态按输入 ID 输出。远场满足 `s/d < theta` 才使用单极子近似；包含目标的节点必须展开，叶内逐粒子求和并排除自身。力仍使用相同的 `G` 和软化长度。
- 输入由 `scripts/generate_cluster.py --n 65536 --seed 42` 生成；`dt=0.001`、`softening=0.01`、`G=1`、Leapfrog、1000 步、`theta=0.5`、block size 128。公平速度对照都使用 `--record off --diagnostics off`，交错运行 3 组，取中位数。完整精度对照额外开启轨迹，仍关闭 CPU 全对势能诊断。

## 规模取舍

| 粒子数与后端 | 1000 步力计算 | 1000 步模拟 | 结论 |
|---|---:|---:|---|
| 4096，`cuda-naive` FP32 | 211.832 ms | 220.954 ms | 直接法足够快 |
| 4096，`cuda-mixed` | 160.587 ms | 169.678 ms | 当前最快的 4096 路径 |
| 4096，`cuda-bh` θ=0.5 | 630.460 ms | 640.079 ms | 不切换；比 FP32 直接法还慢约 3 倍 |
| 65536，`cuda-naive` FP32 | 3648.880 ms | 3662.050 ms | 直接法对照，3 次中位数 |
| 65536，`cuda-bh` θ=0.5 | 2059.600 ms | 2070.870 ms | 完整模拟加速 `1.768×`，耗时下降 `43.5%` |

4096 的数值是相同配置下的一次无轨迹、无诊断运行；差距远大于一般计时抖动，但不能当作精确的多轮中位数。65536 的 3 组原始性能文件保留在服务器 `results/bh_d6_repeat_r{1,2,3}_20260917/` 与 `results/naive_repeat_r{1,2,3}_20260917/`。另有轨迹开启的完整运行：直接法力计算 3636.89 ms、模拟 3716.70 ms；BH 力计算 2056.09 ms、模拟 2128.10 ms。轨迹约 75.8 MiB，模拟计时包含记录时的设备回传等待，不包含末尾文件写入。

## 正确性与近似代价

以同一初态、同样 FP32 数值状态的 `cuda-naive` 1000 步结果作为直接求和参考；所有 65536 粒子的末态和每 10 步的轨迹参与比较。

| 指标 | θ=0.5，六层树 |
|---|---:|
| 最终位置整体相对 L2 | `0.00591341`（0.591%） |
| 最终速度整体相对 L2 | `0.00746214`（0.746%） |
| 最大记录帧位置相对 L2 | `0.00591340`（0.591%） |
| 最终位置每粒子绝对误差 P95 / 最大 | `0.00313429` / `0.00370585` |
| 最终速度每粒子绝对误差 P95 / 最大 | `0.01103741` / `0.01255875` |
| 动量绝对漂移 | BH `1.1761e-5`；直接法 `2.9554e-9` |

全部输出有限。按本次探索采用的整体相对 L2 小于 1% 的工程门槛，θ=0.5 通过；但这是近似算法，不保证每个粒子的误差都低于 1%。节点单极子力不严格满足成对反作用，动量漂移明显高于直接法。没有运行昂贵的 65536 粒子 CPU FP64 全对参考，也没有把关闭的势能诊断冒充完成；这里的误差基准是 GPU FP32 直接法。

## 性能剖析与边界

五层树在前 100 步可快于直接法，但粒子演化后集中到更少的叶节点：按 32³ 网格统计，初态每叶最多约 13 个粒子，末态最多约 154 个。五层树跑满 1000 步时力计算反而达到 7571 ms；改为六层后降到约 2059 ms。因此树深度必须按整个轨迹而非仅初态选择。对六层树的 Nsight Systems 统计显示，遍历 kernel 约占 GPU kernel 时间的 98.5%，建树并非当前主要瓶颈。

`theta=0.7` 的五层树虽在一次 1000 步运行中将力计算降至 3344 ms，但末态位置/速度整体相对 L2 分别升至 1.36%/1.77%，超出本次 1% 门槛。不能只通过增大开角声称优化而忽略误差。

固定深度树针对这组分布有效；若粒子进一步坍缩到少数叶节点，叶内仍会退化为大量直接作用。叶节点质量/质心使用 FP32 原子累加，其顺序可能变化，不能保证不同运行逐位相同。当前版本尚未做空间排序、压缩稀疏树或自适应叶容量；这些是后续优化方向。`--diagnostics final` 当前会用 CPU FP64 遍历全对计算势能，在 65536 粒子速度比较中应关闭并单独计成本。

## 复现

```bash
source /data/nbody-dev/activate-nbody.sh
cmake --build build
ctest --test-dir build --output-on-failure
python scripts/generate_cluster.py --n 65536 --seed 42 --output data/cluster_65536.txt

./build/nbody --backend cuda-naive --block-size 128 \
  --input data/cluster_65536.txt --config configs/cpu_4096.cfg \
  --diagnostics off --output results/cluster_65536_direct_repeat
./build/nbody --backend cuda-bh --theta 0.5 --block-size 128 \
  --input data/cluster_65536.txt --config configs/cpu_4096.cfg \
  --diagnostics off --output results/cluster_65536_bh_repeat
python scripts/compare_runs.py results/cluster_65536_direct_repeat \
  results/cluster_65536_bh_repeat
```

结果目录不能覆盖已有目录。比较纯模拟速度时，两条命令都加上 `--record off`；比较完整轨迹误差时都保留默认的记录开启状态。关于算法背景，可参见 [Barnes 与 Hut 的原始论文](https://www.nature.com/articles/324446a0) 和 [GPU 树算法论文](https://arxiv.org/abs/1106.1900)；本文的速度与精度数字仅来自本项目实测。
