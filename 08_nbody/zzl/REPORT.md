## 1. 任务完成情况

程序解析粒子初态与积分参数，用 CUDA 并行求力并推进状态，把轨迹回传主机写成二进制文件，再由 Matplotlib 渲染二维或三维动画。基础规模为 4096 粒子 1000 步，进阶规模 65536 粒子 1000 步，另以 65537 和 100000 粒子各跑 20 步检查尾块与规模边界。计算后端为 NVIDIA CUDA 与 CPU/OpenMP，国产 GPU 适配列为扩展方向。

测试代码独立保存在 tests/，通过外部进程调用模拟程序。动画支持星团、二体轨道、轨道扰动及近距离筛查。近距离筛查只覆盖保存帧，用于判断离散记录时刻的粒子间距；连续碰撞检测与碰撞合并属于扩展方向。

## 2. 物理模型与积分

软化牛顿引力加速度：
a_i = G Σ_(j≠i) m_j (r_j-r_i) / (|r_j-r_i|²+ε²)^(3/2)。
其中 r_i 为粒子位置，m_j 为源粒子质量，G 为引力常数，ε 为软化长度。加速度由源粒子质量决定。正软化长度避免重合位置的奇异性；零质量粒子可以作为探针。

显式 Euler 用旧速度更新位置，再用旧位置对应的加速度更新速度。
Leapfrog 使用 kick–drift–kick：半步更新速度，更新位置，重新求力，再完成后半步速度更新。
速度保存在整数时间步，便于计算守恒量。Leapfrog 对光滑软化模型具有二阶收敛性质，时间步长需结合轨道尺度和收敛结果选择。

状态和求力使用 float32，守恒量诊断使用 double。GPU 使用 rsqrtf 和默认 FMA，全局快速数学选项保持关闭。
软化势能为 -G Σ_(i<j) m_i m_j / sqrt(r_ij²+ε²)。跨平台比较采用数值容差。

## 3. 实现与优化

每个线程负责一个目标粒子；tiled 内核把源粒子分批读入共享内存并复用，支持 128、256、512 线程块。
尾块中超出粒子范围的线程仍参加同步，填充质量为零。另提供 naive 内核作为对照。

优化与修正在三轮里逐个加入，每一轮都由一个具体问题触发。求力内层原本对每个源粒子都判断一次是否为目标自身，现在只在包含目标粒子的那个 tile 内保留判断，其余 tile 按原顺序直接累加，求和顺序与浮点精度不变。Leapfrog 的末次半步速度更新并入求力内核，每步的 kernel 数由三个降为两个；各线程只写自己的速度，求力只读位置，因此不需要额外的块间同步。小规模长序列改用 CUDA Graph 一次提交多步，批处理停在记录边界，并保留 direct 作为对照。位置、速度、加速度常驻 GPU，三个数组共 48N 字节，记录时回传位置。

零引力路径来自一次正确性修正：G=0 且坐标量级接近 float32 上限时，坐标差溢出会让本应匀速的粒子以非有限状态报错；现在 GPU 侧清零加速度后跳过求力，CPU 侧同时跳过两两循环与势能求和。交付前的复核另改了三处：参数解析不再把紧随其后的选项当作取值，轨迹先发布载荷再写侧文件，以免中断后留下没有轨迹的侧文件，记录点由闭式计算取代整表分配。各轮改动的对照数据与所用输入见第 5 节的内核耗时比较、第 6 节的 Nsight Systems 统计，以及随包的 evidence/submission-benchmark.json 与 evidence/profiling-nsys.json。

轨迹文件先写入粒子数 P 和记录数 R（小端 int32），随后按粒子顺序写入 float32[P][R][3] 坐标数组。文件长度为 8+12PR 字节，包含初态和末态。
JSON 侧文件记录实际步数。先按帧暂存，再按粒子转置。目标块预算 32 MiB，整块覆盖全部粒子时顺序读取。
另有行缓冲与单帧数组；单粒子历史超过预算时允许超出。磁盘约需两份轨迹空间。
32 MiB 为转置块的目标大小；实际内存需求还取决于粒子数与记录数。

Python 读回采用内存映射，每次最多扫描 1 MiB 输入数据以检查非有限值，避免单粒子长历史产生过大的临时数组。
打包前核对源码、测试、工具脚本及程序哈希，并要求全部 CUDA 验收用例执行通过。

|---:|---:|---:|---:|
| 4096 | 1000 | 0.211214 | 5.632152 |
| 65536 | 1000 | 19.880041 | 23.620341 |
| 65537 | 20 | 0.395634 | 0.868012 |
| 100000 | 20 | 1.043032 | 1.614125 |

4096 基础运行包含额外完整 CPU 对照，该行进程时间包含 CPU 对照的执行开销。
计算加速比 22.856 倍，CPU 使用 24 个线程。

相同输入、记录频率与最终状态输出，CPU（24 个线程）与 GPU 交替各运行三次：
完整进程中位数 CPU 5.264115 s，
CUDA 1.033609 s，整体加速比 **5.093 倍**。
完整进程时间包含进程启动、CUDA 上下文创建与 /mnt/d 文件输出；上下文创建在两次测量中占
0.14～0.45 s，因此该加速比随主机状态波动，比较计算区间时以本节的计算加速比为准。
此结论仅适用于本机与当前配置。

CUDA Event 分段计时包含积分、初始求力与可能的提交空闲，排除预热、记录回传和写盘；主机区间另记。
trajectory_spool_seconds 包含初态及后续追加帧；
trajectory_finalize_seconds 包含转置收尾；final_state_write_seconds 是最终状态写出。
final_output_seconds 覆盖后两者。device_allocation_bytes 仅表示三个设备数组，其统计范围为模拟状态数组。

## 6. 性能分析与适用范围

本实现采用 O(N²) 的直接求力算法和单精度状态存储。Barnes–Hut、双精度状态计算与异步轨迹回传可作为后续扩展。
扩展实验可比较树算法的计算时间与近似误差，并评估页锁定内存和双缓冲对轨迹回传耗时的影响。

Nsight Systems 2026.5.1.161-265138896106v0 在 4096 粒子、5 步的 direct 短任务中采集了 CUDA 时间线：
tiled 求力 9 次，平均 196.991 μs；naive 求力同样 9 次，平均 533.190 μs，naive 与 tiled 的平均耗时之比约为 2.707 倍。两者使用相同输入与采集配置，
统计包含预热和正式计算调用，该比值描述求力内核耗时，第 5 节给出完整进程加速比。CUDA API 总时间含一次性初始化和 profiler 开销，内核比较采用 CUDA 内核时间统计。

此前 Windows Compute Sanitizer 受 WDDM 调试接口限制；Nsight Compute 2025.1.1 在当前
RTX 5060 Laptop / WSL 组合中记录了初始化错误。因此本报告的性能结论以运行计时和 CUDA 时间线为依据。原始记录和
Nsight Systems 统计随包保留。
交付程序及验收环境为 WSL/Linux。Windows 平台可按 README 中的工具链要求从源码构建。
