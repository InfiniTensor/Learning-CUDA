# 题目 3 总结报告：Hadamard 加速与量化融合

训练营 ID：**曹泽阳**；GitHub ID：`zmuxuny`。

实现 FP16/BF16 Hadamard 变换及 MXFP8/NVFP4 量化融合，提供蝶形与原生矩阵指令两类路径。输入头维度支持 1–1024 的 2 的幂，覆盖题目要求的 64/128/256；支持归一化、固定随机符号和随机舍入。矩阵与融合路径均保留独立对照，按实测比较其收益。

## 算法与融合设计

采用自然顺序 Sylvester 矩阵，`H_1=[1]`、`H_2D=[[H_D,H_D],[H_D,-H_D]]`。默认 `y=x H_D/sqrt(D)`；随机符号模式先将各列乘以由种子确定的 ±1，再变换。

**蝶形路径**每级将一对 `(a,b)` 变为 `(a+b,a-b)`，按跨度 1、2、4…组合，共 log₂D 级，复杂度 O(D log D)。CUDA 及兼容后端通过 XOR shuffle 和寄存器交换，Ascend 在 UB 中用标量/向量加减；均使用 FP32 中间量，最后舍入回输入 dtype。

**分解矩阵路径**使用 `H_D=H_(D/16) ⊗ H_16`：以 FP16/BF16 原生矩阵指令计算 H16、FP32 累加，再用蝶形完成剩余因子。NVIDIA 使用 MMA，MACA/CoreX/MUSA 分别处理原生 fragment 布局；Ascend 使用 Cube Mmad/Fixpipe 与 AIV 后处理。复杂度仍为 O(D log D)。CUDA 及兼容后端另保留 O(D²) 的 FP16 稠密 WMMA 对照，该路径与分解矩阵分别记录。小于 16 的维度不走 H16 分解。

**融合量化**在量化前先舍入回 FP16/BF16，使结果与先保存变换输出再量化一致。MXFP8 只依赖局部块最大值，可在一次变换中完成量化。NVFP4 需要全张量最大值，因此比较三种完整流程：

| 路径 | 工作内容 | 主要代价 |
|---|---|---|
| 非融合 | 变换写回 → 独立量化（含全局 amax） | 中间张量写回/读取及归约 |
| 全融合 | 变换求 amax → 重算变换并量化 | 两遍变换 |
| 写回 + amax | 变换时同时写回和求 amax → 量化 | 中间张量搬运，省去单独 amax 遍历 |

因此更少的 kernel 不保证更快。Ascend 矩阵路径还包含 FP32 中间结果的 GM 交接，这部分计入耗时。代码入口为 [主程序](src/main.cu)、[蝶形](src/hadamard.cuh)、[CUDA 矩阵路径](src/tensor_core.cuh)、[Ascend 调度](ascend/hadamard.hpp) 和 [Cube 内核](ascend/cube.cpp)。

## 性能与路径选择

最终方案取各平台 `comparison.json` 的 `after` 项，起始基线的数据来源在总收益表后说明。每项 3 个独立进程，预热后用设备事件计时，取中位数；包括完整变换或量化流程所需全部 kernel，排除 CPU 参考、分配、文件 I/O 和主机传输。输入为 seed=42 正态数据，开启归一化、关闭随机符号；重复次数及环境见平台报告。随机符号另由正确性测试覆盖。

### 起始基线到最终实现的总收益

总加速比 = 基线耗时 / 最终耗时；耗时减少 = 1 − 最终耗时 / 基线耗时。下表均为 FP16、65536×1024（128 MiB）、正态输入、默认块缩放及 nearest，单位 ms。

比较完整“Hadamard 变换＋量化”，包含 NVFP4 的全局 amax。两端分别使用各自已测最快的完整方案；表内列出路径，避免用较慢方案充当基线。最终方案需显式配置，并非程序自动分派。

| 平台 | 格式 | 基线方案 → 最终方案 | 基线 ms | 最终 ms | 总加速比 | 耗时减少 |
|---|---|---|---|---|---|---|
| RTX 4090 D | mxfp8 | 蝶形融合 → 矩阵融合 | 0.65744 | 0.21593 | 3.04× | 67.2% |
| RTX 4090 D | nvfp4 | 蝶形融合 → 矩阵融合 | 1.09036 | 0.35407 | 3.08× | 67.5% |
| C500 | mxfp8 | 矩阵非融合 → 矩阵非融合 | 0.73246 | 0.52080 | 1.41× | 28.9% |
| C500 | nvfp4 | 矩阵非融合 → 矩阵写回+amax | 1.14481 | 0.83216 | 1.38× | 27.3% |
| MR-V100 | mxfp8 | 矩阵非融合 → 矩阵非融合 | 0.99989 | 0.99969 | 1.00× | 0.0% |
| MR-V100 | nvfp4 | 矩阵非融合 → 矩阵写回+amax | 1.57946 | 1.10027 | 1.44× | 30.3% |
| S4000 | mxfp8 | 蝶形非融合 → 蝶形非融合 | 1.77218 | 1.75613 | 1.01× | 0.9% |
| S4000 | nvfp4 | 蝶形非融合 → 蝶形非融合 | 37.06536 | 3.97626 | 9.32× | 89.3% |
| Ascend 910B2 | mxfp8 | 蝶形融合 → 矩阵融合 | 337.40440 | 133.83687 | 2.52× | 60.3% |
| Ascend 910B2 | nvfp4 | 蝶形非融合 → 矩阵非融合 | 569.70426 | 165.99768 | 3.43× | 70.9% |

NVIDIA 起始基线为 `0a5e40b`，国产平台为同设备正确性通过的基础移植，具体配置与二进制指纹见平台报告。NVIDIA 两端来自同卡同配置的分批归档测量；国产平台来自基线/最终交替测量，各取 3 次独立进程的中位数。所有比值均直接由端点耗时计算，不相乘阶段加速比，也不对不同平台取一个平均倍数。

[逐项总收益与数据来源](results/performance_summary.json) 由 `python3 tests/report.py` 从原始 JSON 生成；[NVIDIA 完整尺寸表](REPORT_4090D.md) 包含常规输入、两种 dtype、最终软件及原生转换对照。

### 最终实现的矩阵与蝶形比较

FP16、65536×1024（128 MiB）独立变换，单位 ms；比值为同一归档版本的蝶形耗时除以矩阵耗时，大于 1 表示矩阵更快。

| 平台 | 蝶形 ms | 分解矩阵 ms | 蝶形 / 矩阵 |
|---|---|---|---|
| RTX 4090 D | 0.28853 | 0.28593 | 1.01× |
| C500 | 0.47257 | 0.25575 | 1.85× |
| MR-V100 | 0.89576 | 0.48758 | 1.84× |
| S4000 | 0.99830 | 1.39601 | 0.72× |
| Ascend 910B2 | 120.42426 | 63.55028 | 1.89× |

C500、MR-V100、Ascend 在这组大输入上适合矩阵分解；S4000 的矩阵实现通过数值验证，但应选择更快的蝶形。此表只比较最终独立变换的算法选择；整个提交的优化收益以上面的完整流程对照为准。

### NVFP4 融合的完整成本

FP16，单位 ms。三列均为分解矩阵路径，下表用于比较同一设备、同一输入下的执行方式。

| 平台 | 形状 | 非融合 | 全融合（重算） | 写回 + amax |
|---|---|---|---|---|
| RTX 4090 D | 8192×1024 | 0.03814 | 0.03611 | 0.03722 |
| MR-V100 | 8192×1024 | 0.18826 | 0.27475 | 0.15633 |
| Ascend 910B2 | 65536×1024 | 165.99768 | 191.62059 | 172.29744 |

MR-V100 此尺寸的写回方案优于重算，Ascend 此尺寸的非融合更快。S4000 的 128 MiB FP16/NVFP4 则以蝶形非融合 3.97626 ms 优于蝶形全融合 16.18210 ms。MXFP8 无全局 amax 依赖，4090 D 的 8192×1024 分解矩阵融合为 0.01865 ms，可选 Ada FP8 转换对照为 0.01587 ms。其他形状与 dtype 见各平台完整表，默认输出仍为蝶形结果；矩阵与写回方案须用 README 的独立参数测量/导出。

### 同功能 CPU 对照

RTX 4090 D、FP16，比较单独变换；GPU 时间包含输入 H2D、蝶形变换、输出 D2H，不含量化或文件 I/O。CPU 是本项目单线程 float64 蝶形参考，GPU 中间量为 FP32，因此这些结果验证的是相对项目参考的收益，不是同精度优化 CPU 库的横向排名。

| 行数×维度 | CPU ms | GPU 含传输 ms |
|---|---|---|
| 32×64 | 0.0381 | 0.0103 |
| 8192×64 | 9.3528 | 0.2500 |
| 8192×128 | 19.2215 | 0.5825 |
| 8192×256 | 37.1305 | 0.7309 |

小批量收益受启动与传输成本影响，按表内尺寸解释，不将大输入收益外推到所有形状。

## 旋转对量化误差的影响

旋转质量实验在反变换回原坐标系后比较 MSE。1024×128 FP16 的异常值样本中，NVFP4 直接块量化 MSE 为 0.0185736，旋转后重建为 0.0442362；正态样本为 0.00912241 与 0.00903669。细粒度块缩放已能隔离部分异常值，随机旋转在这些样本上未稳定改善误差。该提交验证变换与融合算子，未进行端到端模型精度实验。[该配置的原始实验](results/rotation_quality.json)。
